PR comment responder

I led the work on an agent stage that checks each review comment against the current commit, records a verdict for every thread, posts corrected suggestions inline, and resolves only the threads its verdict allows.

Built in 2026 · Part of my AI developer tooling work

Problem and constraints

AI reviewers and Copilot added review comments faster than people could triage them. Some comments were right, some were wrong, and some suggested code that wouldn't compile. A responder agent had to work through them.

  • It runs on a shared agent platform where the worker shell has no GitHub credential. It can write only through the platform's tools.
  • It doesn't push commits or open PRs in this stage. It only responds to comments.
  • Threads that still need a person must stay open.
  • The summary must match what the agent did.

Architecture

flowchart TD
  R[Review comments: AI reviewer, Copilot, people] --> T[Trigger carries PR and base branch]
  T --> W[Responder worker]
  W -->|fetch threads| PT[Platform tools]
  W --> V[Verify each comment at the current head]
  V --> D[(Dispositions: verdict, verified span, replacement, reason)]
  D --> IR[Inline suggested-change review]
  D --> RS[Resolve allowed threads]
  D --> SM[Summary rendered from dispositions]
  IR & RS & SM --> PT
  PT --> PR[Pull request]

The agent's main output is a dispositions list. For each thread it records a verdict, the exact code span the agent checked, an optional replacement, and a reason. The inline review, thread resolutions, and summary on the PR are all generated from that list.

Verdict logic

flowchart TD
  A[Thread] --> B{Still valid at current head?}
  B -->|code moved| X[Drop stale anchor and log it]
  B -->|yes| C{Comment accurate?}
  C -->|accurate, needs a human| L[Leave open]
  C -->|medium or low, not legitimate| RZ[Resolve with a one-line reason]
  C -->|suggestion is wrong| CO[Resolve and post a corrected inline suggestion]
  C -->|needs a different fix| SN[Suggest a new fix, leave open]

Only the "resolve" and "correct-inaccurate" verdicts close a thread. Threads marked "leave-accurate" or "suggest-new-fix" stay open for a person. The agent also checks Copilot's suggestion blocks. It leaves accurate ones alone, and resolves inaccurate ones and replaces them with a corrected inline suggestion.

Changes after each test round

We shipped this in short rounds, and each round fixed something a test run exposed.

  1. A synthetic run showed the worker had no GitHub API access, and both git and the GitHub CLI failed. The agent now reads and resolves threads through platform tools and emits dispositions as structured output.
  2. A later run resolved all five threads, including two that had to stay open. Its summary said "no corrections" while the dispositions held two. Now only specific verdicts resolve threads, and the summary is rendered directly from the dispositions.
  3. At first a dispatcher workflow posted the inline review and checked every span against the head commit. When the platform added a review-comment tool, the worker started posting under its own identity, and we removed the dispatcher's extra write permission.

Failure modes and guardrails

FailureGuardrail
The run ends without a reportA summary comment is required, so the agent can't finish in an unknown state.
Stale anchorsSpans are checked against the current head. Stale ones are dropped and logged.
Resolving threads that should stay openResolution depends on the verdict, not on the model's judgment.
Scope creepThis stage makes no commits, pushes, or new PRs, and doesn't re-request Copilot.
Broad permissionsWrites go through scoped platform tools.

Tradeoffs and alternatives

  • Letting the agent fix code directly would combine judging a comment with changing code, and it would need credentials the platform withholds.
  • A free-text summary drifted from what happened in testing. A summary rendered from the dispositions can't.
  • Resolving every thread the agent answered would hide threads that people still need to see.

Next steps

  • Track how often people reopen or override verdicts, as a quality signal.
  • Pass verdicts to the PR reviewer, so it repeats refuted findings less often.
